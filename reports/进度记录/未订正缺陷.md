# MP-3000A 数据的未订正缺陷分析

## 概述

使用 `54623_MP_3000A_ERA5Model_20231101_20240331_areamean_selfgb.nc` 训练 MWR 廓线反演模型时，发现以下数据质量问题。这些问题制约了模型精度，标注了严重程度和修复方向。

---

## 缺陷 1：K 波段亮温严重云污染 — 严重

### 现象

K 波段（22-31 GHz）的观测亮温（Obs_BT）存在大量异常样本，OMB（观测−模拟亮温）远超正常范围：

| 通道 | 频率 | 极端样本数 | OMB p95 | OMB p99 |
|------|------|-----------|---------|---------|
| ch0 | 22.2 GHz | 275 | +5.3 K | +10.7 K |
| ch1 | 22.5 GHz | 275 | +5.0 K | +10.4 K |
| ch2 | 23.0 GHz | 261 | +5.3 K | +10.7 K |
| ch3 | 23.8 GHz | 258 | +4.1 K | +10.3 K |
| ch4 | 25.0 GHz | 283 | +4.0 K | +11.4 K |
| ch5 | 26.2 GHz | 283 | +3.5 K | +11.9 K |
| ch6 | 28.0 GHz | 288 | +3.0 K | +12.0 K |
| ch7 | 30.0 GHz | 294 | +3.4 K | +13.7 K |

极端样本的 OMB 可达 +50 到 +104 K。

### 机制

K 波段对液态水敏感。云中液态水发射微波辐射，导致亮温显著高于晴空。QC_Flag 和 Rain_Flag **未能标记这些样本**（它们通过了 QC=0, Rain=0 的过滤）。

### 影响

- 训练时这些极端样本会造成 loss 振荡，T_0-2km 模型的 7% 样本（>5K RMSE）由此产生
- V 波段通道 R² 达 0.92-0.98，K 波段仅 0.49-0.87
- 线性回归 BT 订正对 K 波段偏差有效（纠正系统性偏移），但无法消除云噪声的非线性成分

### 当前 v2 的处理

- K 波段 OMB > 50K 的样本直接删除（约 10 个极端值）
- 逐通道线性 BT 回归订正（将 Obs_BT 对齐到 Sim_BT）
- **不足：** 未处理中等 OMB（10-50K）的样本，这些仍混入训练

### 建议修复

1. **论文方法**：用 Sim_BT 代替 Obs_BT 作为训练输入，仅在评估时使用 Obs_BT
2. **数据驱动方法**：对全部 K 波段通道，OMB > 3σ 的样本标记为云污染并排除
3. **物理方法**：利用 Column_Liquid_Cloud 变量，显式排除 CLWC > 阈值的廓线

## 缺陷 2：Sim_BT 与 Obs_BT 之间的 Domain Gap — 严重

### 现象

用 Sim_BT（RTM 模拟亮温）训练的模型，在 Obs_BT（实测亮温）上评估时精度退化严重：

```
训练输入      测试输入      T_RMSE    RH_RMSE
Sim_BT       Sim_BT       0.72 K    5.08%    ← 模型内在能力
Sim_BT       Obs_BT(订正)  2.65 K   12.00%    ← 实际退化 3.7×
Sim_BT       Obs_BT(原始)  6.49 K   19.85%    ← 退化 9×
```

### 机制

1. **K 波段 R² 过低**：22-30 GHz 的 Sim/Obs R² 仅 0.49-0.87
2. **V 波段中低层通道也有偏差**：51-53 GHz 的 R² 仅 0.42-0.58
3. **云液态水未被 Sim_BT 完整建模**：ERA5 的 CLWC 是柱含量，缺乏垂直分布信息
4. **IR_Temperature** 信息（-76°C 到 +15°C）未放入 Sim_BT 模拟框架

### 当前 v2 的处理

直接在订正后的 Obs_BT 上训练和测试，避免了 Sim→Obs 的 domain gap。
代价：Obs_BT 的噪声直接进入损失函数，限制了精度上限。

### 建议修复

1. **混合训练**：70% Sim_BT + 30% Obs_BT(订正)，利用 Sim_BT 的稳定性同时保留真实信号
2. **对抗域适应**：训练一个域分类器，使模型对 Sim/Obs 输入产生一致的反演结果
3. **论文完整 QC 流程**：湿度缩放 → 四季订正 → LWC 筛选 → 逐通道 BT 线性订正，完成后用订正后的 ERA5 廓线重新模拟 BT

## 缺陷 3：K 波段 OMB 呈现明显的厚尾分布 — 中等

### 现象

K 波段 OMB 分布高度非高斯：

```
通道  频率     p5     p50    p95    p99    偏度
ch0   22.2    +0.5   +2.5   +5.3  +10.7   正常
ch7   30.0    -0.3   +0.3   +3.4  +13.7   厚尾
```

p99 是 p95 的 2-4 倍，说明分布有显著右尾。线性回归在厚尾分布的噪声上效果有限。

### 影响

- 逐通道线性 BT 订正将 OMB 均值校正为 0，但厚尾样本的标准差残差仍达 2.6-3.3 K
- 训练时这些样本产生 outlier loss，导致梯度噪声

### 当前 v2 的处理

- V 波段稳定通道的 OMB > 3.5σ 样本删除
- **不足：** 只屏蔽了最极端的异常值，中等异常值仍在训练集中

### 建议修复

1. **Robust 回归**替代 OLS：使用 Huber 或 RANSAC 回归进行 BT 订正
2. **Winsorize** K 波段 OMB：将 OMB > 95th percentile 的值钳制到 95th

---

## 缺陷 4：数据划分存在隐式信息泄露 — 中等（v2 已修复）

### 现象

v1 使用时间顺序划分（70/15/15），但同一廓线在 6 小时内被多次观测。这导致：

- 训练集和测试集可能包含同一廓线不同时刻的观测
- 模型学到的是"记住这个廓线"而非"从亮温反演"

### 影响

- v1 T RMSE = 3.03 K（可能被低估）
- 修复后 v2 T RMSE = 1.45 K（实际上**更好**，说明泄露并未大幅虚高精度）

### v2 修复

按 Profile_Index 将同一廓线的所有观测分配到同一集合，消除跨集合信息泄露。

---

## 缺陷 5：BT 线性订正的泛化局限性 — 中等

### 现象

逐通道线性回归 `Obs_BT → Sim_BT` 产生的系数有极端情况：

```
通道  K 波段斜率  V 波段低层斜率
ch4   0.757       —
ch6   0.656       —
ch8   —           0.496
ch9   —           0.521
```

某些通道的斜率偏离 1.0 很大（ch6 仅 0.656），说明这些通道的 Obs_BT 在动态范围上显著小于 Sim_BT（可能被云衰减压低）。

### 影响

BT 订正没有固定物理基础——当测试集是新的季节或天气条件时，订正系数的外推效果不确定。

### 建议修复

1. 按季节/天气状况（CLWC 阈值）分别计算订正系数
2. 使用物理约束：斜率应在 [0.8, 1.2] 范围内，截距不超过 ±5K

## 缺陷 6：Sim_BT 本身存在质量问题 — 低优先级

### 现象

即使是被当作"真值"的 Sim_BT，其与 ERA5 廓线的一致性也不完美：

- 22.2-23.8 GHz 的 Sim_BT 标准差 4.7-6.2 K，而 54-59 GHz 更高达 5.1-6.3 K
- 同一廓线在数小时内被重复观测时，Sim_BT 的廓线内方差约已计算 K² 量级

### 机制

Sim_BT 来自 RTM 模拟，使用的是 ERA5 背景场而非实测廓线。ERA5 廓线本身的插值误差、云参数化误差都会传导到 Sim_BT。

### 影响

把"有噪声的 Sim_BT"当作干净标签训练，会把 RTM 的系统偏差编码进模型权重。

## 缺陷 7：RTM 辐射传输模型改进路线（2026-06-16）

当前项目同时维护两套 RTM——Python 简易模型（`src/brightness_temp.py`）用于快速验证，MonoRTM v5.6 用于精确计算。但 Python 模型误差极大（K 波段偏 195 K），MonoRTM 在 ARM64 上调试了 3 天才跑通（TAPE3 ASCII→二进制转换、Fortran 兼容性修复），维护成本高。以下四条改进路线按投入产出比排列：

### 路线一（短期，≈0 投入）：MonoRTM 规模化投产

当前 MonoRTM 已稳定运行，`bulk_sim_monortm.py` 管线就绪，只等 ERA5 气压层数据到位即可批量生成约 30 万条训练样本。无需修改任何代码。瓶颈仅在于 CDS 下载速度。

### 路线二（中期，1–2 周）：PAMTRA 替代 MonoRTM

PAMTRA（汉堡大学，`conda install pamtra`）是 Python 原生的微波 RTM，内建 HITRAN 读取、支持云散射、ARM64 原生兼容。替代后可省去 Fortran 编译维护、TAPE3 格式管理、手动 wrapper 封装，并支持定量分析云液态水对 K 波段的亮温增量（为 OMB 阈值设定提供物理依据）。预估模拟速度提升约 5×。

### 路线三（长期，4–8 周）：RTM 物理约束嵌入 BRNN 损失函数（PINN）

在现有 MSE + 平滑正则化的 loss 中增加 RTM 一致性项：

```
L_total = L_MSE + λ₁||∇²ŷ||² + λ₂||RTM(ŷ) − Obs_BT||²
```

第三项将 BRNN 输出的廓线 ŷ 喂回 RTM 模拟亮温，要求与实测 Obs_BT 一致。BRNN 本身可微，RTM 的输出对输入廓线的导数可通过自动求导穿过，无需显式计算 Jacobian。该方法（Physics-Informed Neural Network）在微波廓线反演领域是 2023–2024 年活跃方向，若实现可投 AMT / IEEE TGRS。

### 路线四（论文级）：Python RTM 升级为快速逐线模型

废弃当前单线近似的 `_oxygen_absorption` / `_water_vapor_absorption`，改用 HITRAN 谱线数据库的 Python 读取（`hapi` 库）+ Voigt 线型逐线积分。保留在 Python 生态内可自动求导，但精度接近 MonoRTM。投入较大（需实现全谱线积分、跨层光学厚度优化），收益是可嵌入 PINN 的 autograd 链。

### 路线对比

| 路线 | 投入 | 速度 | 精度 | 散射 | 可微 | 适用场景 |
|------|------|------|------|------|------|---------|
| ① MonoRTM 规模化 | ≈0 | ~10/s | ★★★★★ | 无 | 否 | 批量离线生成训练集 |
| ② PAMTRA 替代 | 1-2周 | ~50/s | ★★★★ | ✅ | 否 | 日常研发 + 云分析 |
| ③ RTM in PINN | 4-8周 | ~1/s | ★★★★ | 可选 | ✅ | 物理约束训练 |
| ④ Python 逐线 | 3-6周 | ~5/s | ★★★★ | 可选 | ✅ | PINN 前置条件 |
