### 1.3 MonoRTM 通道

来源：`src/monortm_wrapper.py`

| 属性 | 值 |
|------|-----|
| 频率来源 | `config.ALL_CHANNELS`（HATPRO 14ch） |
| 灵活性 | `_make_monortm_in(frequencies_ghz, ...)` 接受任意频率列表 |
| 限制 | `simulate()` 调用时固定传入 `self.frequencies` |
| 解析 | `_parse_output()` 按最近频率匹配（±0.5 GHz） |

**结论**：MonoRTM 底层支持任意频率，但 Python wrapper 和 ForwardModel 均硬编码为 HATPRO 14ch。

## 3. 通道不一致分析

### 3.1 关键阻塞

```
BRNN v4 (MP-3000A 22ch + 6 surface features)
    ↓ 通道数不匹配
OEM/MonoRTM (HATPRO 14ch)
```

**问题**：
1. BRNN v4 输入是 22ch Obs_BT + 6 地面特征 = 28 维
2. OEM ForwardModel 输出是 14ch HATPRO BT
3. MonoRTM wrapper 当前硬编码 14ch
4. 无法将 BRNN v4 输出直接用作 OEM 的 `x_a`

### 3.2 两条桥接路线

#### 路线 A：22ch 直接桥接（需 MP-3000A Obs_BT）

```
前提：拿到 MP-3000A NC 文件 + 通道频率表
步骤：
  1. 从 NC 文件提取 Central_Frequency → 22ch 频率列表
  2. 修改 MonoRTM wrapper 支持自定义频率（底层已支持，仅需暴露参数）
  3. 训练 22ch MonoRTM ForwardModel
  4. BRNN v4 输出 → x_a → MonoRTM 22ch H(x) → OEM
```

#### 路线 B：14ch 适配（无 MP-3000A Obs_BT）

```
前提：不需要 MP-3000A 原始数据
步骤：
  1. 用 ERA5 profiles + MonoRTM 14ch 生成训练样本
  2. 训练 14ch BRNN（或用 v4 残差统计迁移）
  3. 14ch BRNN → x_a → MonoRTM 14ch H(x) → OEM
  注意：不能称为"BRNN v4 融合"，应称为"14ch 适配模型"
```
