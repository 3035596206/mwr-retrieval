# 液态水建模拓展方案 — 云天反演能力提升

> 创建日期：2026-05-12
> 状态：后续拓展（当前第3章 BRNN 复现为主要目标，此文档为远期路线图）
> 前置依赖：ERA5 数据就绪、MonoRTM TAPE3 可用、BRNN 基线模型训练完成

---

## 背景

论文第3章 BRNN 算法的核心局限（论文 §3.5.1 自述）：

> "质控减少了廓线样本的变化性，训练样本中只考虑了晴天和液态水含量较小的部分云天样本。云水含量较大情况下的建模需要进一步的研究。"

当前代码现状：

| 维度 | 液态水参与方式 |
|------|-------------|
| 前向 BT 模拟 | `_cloud_absorption()` 基于 Rayleigh 近似计算，LWC 影响全部 14 通道 |
| QC 流程 | ICLWC > 1250 g/m² 删除，750-1250 按比例缩放（`screen_and_scale_lwc`） |
| BRNN 输入 | **无** — 14 通道亮温 + 地面 T/RH/P，不含 LWC 特征 |
| BRNN 输出 | **无** — 仅预测 T 和 RH，不预测 LWC |

核心问题：BRNN 对液态水的处理是"被动感知 + 质控剔除"，在 ICLWC > 1250 的云天场景下不可用。下文提出三个渐进式拓展方案。

---

## 方案一：BRNN 直接输出 LWC 廓线（低侵入性）

### 思路

将现有 6 模型架构扩展为 9 模型（3 高度区间 × 3 变量：T, RH, LWC），直接预测液态水廓线。

### 架构变更

```
当前 6 模型：
  T_0-2km, T_2-8km, T_8-10km
  RH_0-2km, RH_2-8km, RH_8-10km

扩展 9 模型（+3 个 LWC 子模型）：
  T_0-2km, T_2-8km, T_8-10km
  RH_0-2km, RH_2-8km, RH_8-10km
  LWC_0-2km, LWC_2-8km, LWC_8-10km   ← 新增
```

### 关键设计问题

**1. 训练目标从何而来？**

LWC 真值来源质量排序：
- **ERA5 CLWC**：ERA5 在 137 层模式层上有比湿和云液态水含量，插值到 37 层气压层后可用。优势是与 T/RH 训练集同源同时间，劣势是 ERA5 的 CLWC 是模式预报量而非观测，在量值上可能有系统偏差（论文 §3.2 已指出这点）
- **探空 LWC 估算**：当前代码 `sounding_process.py:149-186` 中已有基于 RH 的经验估算（RH<85%→0, >95%→0.5g/m³, 中间线性）。该方法的精度仅适用于晴空和薄云，不适合作为神经网络的训练目标
- **MonoRTM 反演**：迭代调整 LWC 廓线使模拟亮温匹配观测亮温，但这是反演问题，与训练目标循环依赖
- **CloudNet / CloudSat 等主动遥感产品**：精度最高但时空匹配困难

**推荐路线**：优先使用 ERA5 CLWC（从气压层数据中的比云液态水含量变量），与 T/RH 训练集完全同源。

**2. 输出归一化范围**

T 用 Sigmoid 归一化到 [250, 300] K，RH 归一化到 [0, 100]%。LWC 的范围需单独设计：

```python
# LWC 典型值：0-2 g/m³（高层几乎为 0，积云中可达 1-2 g/m³）
# Sigmoid 范围：[0, 2] g/m³
LWC_pred = sigmoid_output * 2.0  # [0, 2] g/m³
```

更精细的方案可按高度区间使用不同的归一化范围：
- 0-2km: [0, 2.0] g/m³（边界层积云 LWC 较高）
- 2-8km: [0, 1.0] g/m³（中层云）
- 8-10km: [0, 0.2] g/m³（高层卷云，LWC 极低）

**3. 样本不平衡**

LWC 的高度稀疏性（大部分层 LWC=0）会导致：
- 训练时损失函数被零值主导，模型倾向于始终输出 0
- 评估指标（RMSE）在大范围零值下失去意义

缓解策略：
- 训练时对 LWC > 0 的层加权（如 ×10 权重）
- 分别评估：全层 RMSE + 非零层 RMSE + 云天样本整层 RMSE
- 使用分位数损失（quantile loss）而非 MSE

### 代码改动量

- `brnn_model.py`：`BRNNEnsemble.__init__` 中增加 `for var in ["T", "RH", "LWC"]`，约 5 行改动
- `train.py`：`prepare_training_data` 增加 LWC 目标处理，约 10 行
- `evaluate.py`：增加 LWC 评估指标和可视化，约 30 行
- `config.py`：增加 LWC 归一化参数，约 5 行

**改动量**：~50 行，低风险。可先基于合成数据验证可行性。

## 方案二：LWC 敏感特征工程（最低侵入性）

### 思路

不修改 BRNN 输出结构，而是在**输入端**显式引入液态水敏感特征，使现有 6 模型的 T/RH 反演在云天条件下更鲁棒。

### 物理基础

Rayleigh 近似下，液态水的体积吸收系数：

$$k_m = \frac{6\pi}{\lambda} \cdot 10^6 \cdot \text{Im}\{-K_w\}$$

其中 $K_w = (\varepsilon_w - 1) / (\varepsilon_w + 2)$，$\varepsilon_w$ 为纯水复介电常数。吸收系数近似 ∝ 1/λ，即**频率越低对液态水越敏感**。

RPG HATPRO 14 通道中对 LWC 的敏感性排序：

| 通道 | 频率 (GHz) | LWC 敏感性 | 其他主要影响 |
|------|-----------|-----------|------------|
| K1 | 22.24 | 中等 | H₂O 线吸收 |
| K7 | **31.40** | **最高** | 液态水指示通道 |
| V1-V3 | 51.26-53.86 | 低（远翼区） | O₂ + H₂O 连续吸收 |
| V4-V7 | 54.94-58.00 | 极低（近线心） | 几乎仅 O₂ |

31.4 GHz 通道是天然的液态水指示器，论文 §3.2.2 中也利用 31.4 GHz 模拟亮温与 ICLWC 的关系进行质控阈值设定（Fig 3.6）。

### 特征工程设计

**基础方案**：将 31.4 GHz 亮温作为额外输入特征（当前已包含在 14 通道中，但与其他通道权重相同）

```python
# 方案 2a: 显式添加 31.4 GHz 通道指数
# 在 14 通道 BT 基础上追加 1 个额外特征
lwc_index = tbs[:, 6]  # 31.4 GHz 是 K 波段第7通道（索引 6）
X = np.column_stack([tbs, lwc_index, surface_data])  # 14 + 1 + 3 = 18 维
```

**增强方案**：构造差分特征，利用 V 波段近线心通道（对 LWC 不敏感）作为晴空参考：

```python
# 方案 2b: 亮温差分作为 LWC 指示器
# 31.4 GHz 亮温 - 54.94 GHz 亮温（O₂ 线心，几乎不受 LWC 影响）
tb_31p4 = tbs[:, 6]    # K波段 31.4 GHz
tb_54p94 = tbs[:, 10]  # V波段 54.94 GHz
delta_lwc = tb_31p4 - tb_54p94  # 正值越大 → LWC 越高

# 作为第 18 个输入特征追加到 17 维基础特征之后
X = np.column_stack([tbs, surface_data, delta_lwc])  # 18 维
```

**完整方案**：多通道差分 + 归一化：

```python
# 方案 2c: 多个 LWC 敏感差分指数
tb_K = tbs[:, 0:7]    # K 波段（水汽+LWC 敏感）
tb_V = tbs[:, 7:14]   # V 波段（温度敏感，LWC 不敏感）

# 构造 K-V 差分向量（7 维 LWC 指示特征）
delta_channels = np.array([
    tbs[:, i] - tbs[:, 10]  # 每个K通道减 54.94GHz 参考
    for i in range(7)
]).T  # shape: (n_samples, 7)

X = np.column_stack([tbs, surface_data, delta_channels])  # 14 + 3 + 7 = 24 维
# 仅用于 RH 模型（水汽+LWC 关联），T 模型不变
```

### 优势与局限

| 优势 | 局限 |
|------|------|
| 无需 LWC 训练目标 | 不能直接输出 LWC 廓线 |
| 改动量极小（~20行） | 对厚云（ICLWC > 1250）改善有限 |
| 可与方案一叠加 | 依赖 31.4 GHz 通道质量 |
| 物理可解释性强 | 差分特征隐含晴空假设 |

### 代码改动

仅需修改 `prepare_training_data()` 中特征拼接逻辑，对 RH_* 模型追加 LWC 敏感特征。

## 方案三：1D-Var 云天约束（论文第4章路线，高侵入性）

### 思路

将第3章 BRNN 作为**先验估计**，第4章 1D-Var 作为**后验约束**，综合利用背景场（NCEP-FNL）对液态水的先验信息和 MWR 观测亮温，改善云天条件下的反演精度。

### 论文第4章关键组件回顾

| 组件 | 说明 | 论文出处 |
|------|------|---------|
| 背景场 | NCEP-FNL 6h 预报（T, RH, 位势高度） | §4.1.1 |
| 前向算子 | PAMTRA 辐射传输模式（替代 MonoRTM） | §4.1.2 |
| B 矩阵 | 背景误差协方差（NMC 方法：不同预报时效的差值统计） | §4.3 |
| O 矩阵 | 观测误差协方差（14 通道亮温误差统计） | §4.4 |
| 偏差订正 | 3 阶泰勒展开（考虑云影响的非线性订正） | §4.4.2 |
| 优化算法 | Levenberg-Marquardt 迭代 | §4.2.1, 公式 4-13 |

### 混合 BRNN + 1D-Var 架构

```
观测亮温 TBO ──→ BRNN ──→ T_first_guess, RH_first_guess
                              │
                              ▼
              1D-Var (LM 迭代优化)
              代价函数 J(x) = J_b + J_o
                              │
              其中 J_b = (x - x_b)ᵀ B⁻¹ (x - x_b)
                  J_o = (y - H(x))ᵀ O⁻¹ (y - H(x))
                              │
                              ▼
                         T_retrieved, RH_retrieved, LWC_retrieved
```

关键改进点：

1. **背景场 x_b**：BRNN 反演结果（替代 NCEP-FNL），优势是已经过 ERA5 训练集优化，在晴空条件下精度高于 NCEP-FNL
2. **控制向量扩展**：在 T + RH 基础上增加 LWC 作为控制变量（论文第4章的控制向量仅含 T + RH，但 1D-Var 框架天然支持扩展）
3. **B 矩阵扩展**：需要构建 T-RH-LWC 的联合背景误差协方差。LWC 部分的 B 子矩阵可从 ERA5 的 CLWC 变率统计得到
4. **前向算子 H(x)**：MonoRTM case5（云天模式），输入 T + RH + LWC，输出 14 通道亮温
5. **雅克比矩阵 K = ∂H/∂x**：可通过微扰动法数值计算（论文 §5.2.5 方法），对 LWC 的雅克比主要出现在 K 波段通道

### 云天场景下的特殊处理

论文第4章的观测偏差订正方法（3 阶泰勒展开）特别考虑了云的影响：

> "观测偏差订正算法采用一种考虑云影响的3阶泰勒展开订正方法，能提高云天条件下大气温湿的探测精度"

这一方法可直接应用于混合架构中，解决云天条件下 MonoRTM 模拟亮温与观测亮温之间非线性偏差随 LWC 增大而增长的问题（论文 Fig 3.6）。

### 实施路线

| 阶段 | 内容 | 预估工作量 |

## 三方案对比

| 维度 | 方案一：LWC 输出 | 方案二：特征工程 | 方案三：1D-Var |
|------|-----------------|-----------------|---------------|
| 侵入性 | 低（~50 行） | 极低（~20 行） | 高（新模块，~500 行） |

| 建议优先级 | 第3步 | 第1步 | 第2步 |
